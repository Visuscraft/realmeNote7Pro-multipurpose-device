# realmeNote7Pro-multipurpose-device

Turn a realme Note 7 Pro running [Termux](https://termux.dev) into a
multipurpose device that updates itself **live and without any user
interaction**: every push to `main` is packaged by GitHub Actions, published as
a release and picked up by the device within minutes.

```
push to main ──> GitHub Actions ──> release auto-<run> + release.tar.gz
                                   └─> latest.json (repo root)
                                            │  polled over HTTPS
                                            ▼
                                    Termux device (deploy/update.sh --watch)
                                    verify sha256 ─> install ─> restart runtime
```

## Repository layout

| Path | Description |
| --- | --- |
| `.github/workflows/release.yml` | Packages the payload, publishes the release and regenerates `latest.json`. |
| `deploy/` | Installer, updater, debloater and boot hook for Termux. |
| `device/` | Runtime entry point, status collector and shared shell library. |
| `modes/` | The modes the device can run (`idle`, `monitor`, `server`). |
| `stock/` | Factory defaults: configuration, package list and the debloat lists. |
| `dashboards/` | Local status dashboard and its HTTP server. |
| `latest.json` | Manifest generated by CI and polled by every device. |

## Install on the device

Install Termux and (so the device recovers after a reboot) Termux:Boot from
F-Droid, then:

```sh
pkg install -y git
git clone https://github.com/Visuscraft/realmeNote7Pro-multipurpose-device
bash realmeNote7Pro-multipurpose-device/deploy/install.sh
```

That is the only manual step. From now on the device polls `latest.json`,
installs new releases and restarts itself on its own.

## Daily use

```sh
~/.realme-device/current/device/device.sh status        # status as JSON
~/.realme-device/current/device/device.sh start monitor # switch mode
~/.realme-device/current/deploy/update.sh --force       # update right now
~/.realme-device/current/deploy/debloat.sh              # preview the debloat
~/.realme-device/current/deploy/debloat.sh --apply      # disable bloatware
tail -f ~/.realme-device/logs/updater.log               # follow the updater
```

The dashboard is served by the `server` mode on <http://127.0.0.1:8080/>
(set `DEVICE_DASHBOARD_BIND=0.0.0.0` in `~/.realme-device/config.env` to expose
it on the local network).

## Configuration

`stock/config.env` holds the defaults; override any of them in
`~/.realme-device/config.env`:

| Variable | Default | Meaning |
| --- | --- | --- |
| `DEVICE_REPO` | `Visuscraft/realmeNote7Pro-multipurpose-device` | Repository publishing the releases. |
| `DEVICE_MANIFEST_URL` | raw `latest.json` of `main` | Manifest polled by the updater. |
| `DEVICE_HOME` | `~/.realme-device` | Installation directory. |
| `DEVICE_UPDATE_INTERVAL` | `300` | Seconds between update checks. |
| `DEVICE_MODE` | `idle` | Mode started after boot. |
| `DEVICE_DASHBOARD_PORT` | `8080` | Dashboard port. |
| `DEVICE_KEEP_RELEASES` | `3` | Releases kept for rollback. |
| `DEVICE_DEBLOAT_BACKEND` | auto | `root`, `adb` or `direct` backend for `deploy/debloat.sh`. |
| `DEVICE_BLOATWARE_LIST` | `stock/bloatware.txt` | Packages the debloater disables. |
| `DEVICE_SERVICES_LIST` | `stock/services.txt` | Services/settings the debloater turns off. |

## Safety

* Releases are downloaded over HTTPS only and verified against the SHA-256
  published in `latest.json`; a mismatch aborts the update.
* The new release is unpacked next to the running one and activated by an
  atomic symlink swap, so an interrupted update never breaks the device.
* Previous releases stay on disk; `ln -sfn` back to one of them to roll back.
* `deploy/debloat.sh` only *disables* packages, records every value it changes
  and can put all of it back with `--restore`; it runs as a dry run unless
  `--apply` is given.
